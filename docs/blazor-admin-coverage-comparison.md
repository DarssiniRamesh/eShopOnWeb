# Blazor Admin Test Coverage: Before vs After

## Overview
This document compares the Blazor Admin test coverage and test suite status before and after the targeted coverage task. The work introduced a dedicated test project, added unit and component tests, and stabilized component refresh patterns to ensure deterministic rendering in tests. The result is a measurable increase in line and branch coverage for the BlazorAdmin package, with green test runs and reproducible coverage artifacts.

## What Changed
The changes span new tests, test infrastructure, and small stabilization fixes in BlazorAdmin to support deterministic component testing.

- New tests added
  - Authentication: End-to-end tests for CustomAuthStateProvider covering authenticated and unauthenticated flows, Authorization header set, role claims applied, caching TTL, and error paths.
  - Shared UI components:
    - App routing and authorization, including redirects for unauthorized users and NotFound routes.
    - MainLayout render assertions and role-gated navigation.
    - NavMenu interactions including hamburger toggle and active link highlighting when navigating to /admin.
    - Toast component levels (Info, Success, Warning, Error) and lifecycle visibility; ToastService event/timer behavior.
  - Services: Smoke tests for CatalogItemService constructor and basic list retrieval using a mocked HttpClient.

- Test infrastructure
  - Centralized bUnit TestContext factory with pre-configured DI (ToastService, IOptions<BaseUrlConfiguration>, fake lookup and catalog services) and JSInterop in loose mode.
  - Global usings for Blazor, bUnit, xUnit, and shared setups to simplify test files.

- Stabilization fixes in BlazorAdmin (for deterministic, thread-safe UI updates)
  - Helpers/ToastComponent.cs: StateHasChanged calls wrapped in InvokeAsync and OnHide unsubscription added in Dispose.
  - Helpers/BlazorComponent.cs and Helpers/BlazorLayoutComponent.cs: DoRefresh now uses InvokeAsync(StateHasChanged) to avoid dispatcher issues in tests.
  - Tests leverage bUnit’s FakeNavigationManager for route-driven component behavior.

## Remaining Gaps
Despite the improvements, several areas remain to be covered to increase confidence and branch coverage.

- CustomAuthStateProvider
  - Alternate branches in GetAuthenticationStateAsync/GetUser/FetchUser not fully covered (branch points mapped around lines 32–57 and 64–85 in compiler-generated methods).

- MainLayout
  - Missing branches in OnAfterRenderAsync corresponding to switch cases and conditional paths.

- ToastService
  - Alternate branches in ShowToast and HideToast paths (e.g., timing and edge-case flows).

- Services and JS interop
  - CachedCatalog* decorators and the full breadth of HttpService methods (post/put/delete) are currently uncovered.
  - JavaScript wrappers (Cookies, Css, Route, JSInteropConstants) are not covered and can be validated with bUnit’s JSInterop verification.

## How to Reproduce
Use the following command to run tests and produce the same artifacts and coverage reports:

```bash
dotnet test tests/BlazorAdmin.UnitTests/BlazorAdmin.UnitTests.csproj \
  --settings CodeCoverage.runsettings \
  --collect:"XPlat Code Coverage" \
  --logger "trx;LogFileName=TestResults/blazoradmin.trx"
```

After completion, the Cobertura XML will be available under the latest directory in:
- tests/BlazorAdmin.UnitTests/TestResults/<guid>/coverage.cobertura.xml

The TRX will be located at:
- tests/BlazorAdmin.UnitTests/TestResults/TestResults/blazoradmin.trx

## Recommendations
To further improve coverage and resilience:

- Close branch gaps
  - Add tests to cover remaining branches in CustomAuthStateProvider and MainLayout’s OnAfterRenderAsync.
  - Extend ToastService tests to exercise alternate paths and edge conditions.

- Expand service and interop coverage
  - Add tests for BlazorAdmin.Services.* including cached decorators and HttpService methods (POST/PUT/DELETE).
  - Cover JS interop wrappers using bUnit’s JSInterop verification to assert calls and parameters.

- Optional tooling improvements
  - Include coverlet.msbuild configuration to produce deterministic Cobertura output (e.g., tests/BlazorAdmin.UnitTests/TestResults/coverage/coverage.cobertura.xml).
  - Generate HTML reports with ReportGenerator to surface coverage trends in CI.
